# Практические работы по дисциплине «Фронтенд и бэкенд разработка»

Практические задания разделены по веткам репозитория.

В результате выполнения второй контрольной работы (практические 19 - 23) были выполнены следующие задания, посвященные добавлению баз данных (SQL и NoSQL), балансировке и контейнеризации:

## Практическое задание 19
В рамках данного практического задания был разработан полноценный REST API бэкенд на базе фреймворка Express.js. Выполнены следующие задачи:
* Разработка базовых CRUD-операций для управления сущностью «Пользователь».
* Интеграция СУБД PostgreSQL в качестве основного хранилища реляционных данных.
* Использование библиотеки Sequelize ORM для описания структуры таблиц в виде JavaScript-моделей.
* Настройка схем данных со строгой валидацией полей на уровне базы данных и приложения.
* Реализация централизованной логики обработки ошибок с возвратом клиенту понятных HTTP-статусов и JSON-сообщений.
* Настройка безопасного подключения к БД через скрытые переменные окружения `.env`.
* Обеспечение поддержки создания, чтения, обновления и удаления записей пользователей для дальнейшего масштабирования.

## Практическое задание 20
Данная работа была посвящена изучению и внедрению NoSQL подходов к хранению информации в веб-приложениях. Выполнены следующие задачи:
* Полное переписывание части бэкенда (управление пользователями) для работы с документоориентированной БД MongoDB.
* Пересмотр структуры хранимых данных для перехода от жестких реляционных таблиц к гибким JSON-подобным документам.
* Интеграция библиотеки Mongoose для задания строгих схем (Schemas) на уровне кода с сохранением гибкости NoSQL.
* Переработка контроллеров и сервисов для корректного выполнения асинхронных запросов к коллекции MongoDB.
* Настройка работы с уникальными идентификаторами (ObjectId) и обработка вложенных структур данных.
* Оценка различий между SQL и NoSQL базами данных в контексте производительности и масштабирования.

## Практическое задание 21
Для существенного повышения производительности и скорости отклика сервера в архитектуру приложения был внедрен in-memory кэш. Выполнены следующие задачи:
* Развертывание кэша на базе Redis для снижения нагрузки на основную базу данных при часто выполняемых запросах.
* Настройка клиента Redis для установки постоянного соединения с сервером кэширования при старте приложения.
* Разработка специализированных middleware-функций для перехвата GET-запросов и проверки наличия готовых ответов в оперативной памяти.
* Установка оптимальных значений времени жизни кэша (TTL) для различных типов данных (списки товаров, профили пользователей).
* Реализация стратегий инвалидации кэша: принудительная очистка ключей в Redis при любых изменениях данных (POST/PUT/DELETE запросы).
* Существенное сокращение среднего времени ответа сервера благодаря устранению рассинхронизации данных.

## Практическое задание 22
Данный этап был сфокусирован на обеспечении высокой доступности и отказоустойчивости приложения посредством горизонтального масштабирования. Выполнены следующие задачи:
* Развертывание и настройка веб-сервера Nginx в качестве обратного прокси-сервера (reverse proxy) и балансировщика нагрузки.
* Изменение архитектуры приложения для одновременной работы нескольких независимых экземпляров бэкенда на разных сетевых портах.
* Настройка конфигурационного файла `nginx.conf` с блоком `upstream` для объединения рабочих экземпляров в единый пул серверов.
* Настройка равномерного распределения входящего клиентского HTTP-трафика с использованием алгоритма Round Robin.
* Проброс служебных HTTP-заголовков для передачи реального IP-адреса клиента (`X-Real-IP`) и запрошенного хоста.
* Модификация бэкенд-сервисов для возврата уникального идентификатора (`SERVER_ID`) с целью наглядной демонстрации балансировки.
* Ручное тестирование системы на отказоустойчивость при искусственном выходе из строя одного из узлов пула.

## Практическое задание 23
Итоговая практическая работа объединила все предыдущие этапы путем полной контейнеризации микросервисного проекта с использованием экосистемы Docker. Выполнены следующие задачи:
* Создание оптимизированных `Dockerfile` для бэкенда (Node.js) и фронтенд-приложения (React/Vite).
* Реализация сборки фронтенда через паттерн multi-stage build, где финальный образ содержит только Nginx и статичные файлы бандла.
* Разработка конфигурации `docker-compose.yml` для оркестрации и одновременного запуска балансировщика, трех реплик бэкенда и Redis.
* Размещение всех сервисов в единой изолированной виртуальной сети `app-network` для повышения безопасности.
* Адаптация адресов подключения к сервисам для работы во внутренней DNS-сети Docker (полный отказ от использования `localhost`).
* Настройка параметров автоматического обнаружения сбоев `max_fails` и `fail_timeout` (Circuit Breaker) в Nginx для исключения недоступных контейнеров.
* Обеспечение комплексного развертывания всего микросервисного стека в любой среде с помощью одной команды `docker compose up --build`.
