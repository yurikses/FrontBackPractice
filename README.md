# Практические работы по дисциплине «Фронтенд и бэкенд разработка»

Практические задания разделены по веткам репозитория.

## Практическая 13. Service Worker
В рамках работы реализован базовый Service Worker для кэширования статических ресурсов и обеспечения офлайн-доступа:
- **Регистрация**: В `main.tsx` добавлена регистрация Service Worker, который находится в `public/sw.js`.
- **Кэширование**: В `sw.js` реализован обработчик события `install`, который открывает кэш и сохраняет в него основные ресурсы приложения (HTML, CSS, JS). При активации (`activate`) старые кэши удаляются, если их версия не совпадает с текущей.
- **Стратегия Network-First**: В обработчике `fetch` реализована стратегия Network-First. Сначала пробуем получить ресурс из сети, если это не удается (например, при отсутствии интернета), то возвращаем его из кэша. Это обеспечивает актуальность данных при наличии связи и офлайн-доступ при ее отсутствии.

## Практическая 14. Web App Manifest (иконки, display, theme)
В рамках работы настроен Web App Manifest для улучшения пользовательского опыта при установке приложения на устройства:
- **Создание `manifest.json`**: В корне `public` создан файл `manifest.json`, который описывает метаданные приложения, включая имя, короткое имя, начальный URL, цвет фона и темы, а также режим отображения (`display: "standalone"`).
- **Иконки**: В `manifest.json` добавлено несколько иконок разных размеров (16x16, 32x32, 48x48, 72x72, 96x96, 144x144, 192x192, 512x512) с параметром `purpose: "any maskable"`, что позволяет корректно отображать иконки на различных устройствах и при разных режимах установки.
- **Проверка валидности**: Манифест проверен с помощью онлайн-валидатора, и все ошибки были устранены, что гарантирует корректную работу при установке приложения на мобильные устройства и ПК.

## Практическая 15. HTTPS + App Shell (редирект, shell-архитектура)
В рамках данной работы заложен фундамент Progressive Web App (PWA) и безопасности:
- **HTTPS и редирект**: Настроена работа приложения по защищенному протоколу HTTPS с использованием локальных SSL-сертификатов (необходимо для работы Service Worker и Web Push API).
- **App Shell**: В `public/sw.js` реализовано стартовое кэширование каркаса приложения на этапе `install` (кэшируется `/`). Благодаря этому интерфейс приложения загружается мгновенно даже без интернета, а динамические скрипты Vite и запросы к API пробрасываются через стратегию Network-First.
- **Манифест**: Создан и валидирован `manifest.json` с полным набором иконок (от 16x16 до 512x512) и параметром `purpose: "any maskable"`, что позволяет устанавливать приложение на телефон или ПК.

## Практическая 16. WebSocket + Push (realtime + уведомления)
Реализовано мгновенное взаимодействие между клиентами без необходимости перезагружать страницу:
- **Node.js + Socket.io**: В `server.js` поднят WebSocket-сервер. При создании задачи клиент делает `socket.emit("newTask")`, а сервер рассылает событие `io.emit("taskAdded")` всем подключенным пользователям.
- **In-App уведомления**: В React-компоненте `App.tsx` написан хук `useEffect`, слушающий событие `taskAdded`. При получении новой задачи от другого пользователя, если уведомления разрешены, в правом верхнем углу интерфейса на 3 секунды появляется всплывающее окошко «✨ Новая задача добавлена».
- **Динамический список**: Новые задачи реактивно добавляются в стейт и мгновенно отображаются на экране.

## Практическая 17. Детализация Push (subscription, VAPID, обработчик push)
Настроена полноценная работа с системными Push-уведомлениями (на уровне ОС Windows/Android/macOS):
- **Подписка (Subscription)**: В `App.tsx` реализованы функции `subscribeToPush` и `unsubscribeFromPush`. Они запрашивают права через `Notification.requestPermission()`, получают объект подписки из `pushManager` и отправляют его на сервер в `POST /subscribe`.
- **VAPID-ключи**: В `server.js` интегрирована библиотека `web-push`. Для безопасной авторизации сервера с пуш-сервисами браузера сгенерирована и подключена пара ключей (Public / Private VAPID).
- **Обработка в Service Worker**: В `sw.js` добавлен слушатель `self.addEventListener('push')`. При получении скрытого сигнала от сервера, воркер парсит JSON, достает `title` и `body`, и вызывает `self.registration.showNotification()`, прикрепляя иконки приложения и настраивая паттерн вибрации.

## Практическая 18. Подготовка к КР3 (Планирование и Snooze)
Реализован механизм отложенных задач и интерактивных уведомлений:
- **Форма и хранилище**: В интерфейс добавлен инпут `<input type="datetime-local">`. В `localStorage` изменена структура задач: теперь это массив объектов `{ id, value, reminder }`, где `reminder` — это timestamp (число миллисекунд).
- **Планирование на сервере (`setTimeout`)**: В `server.js` реализована проверка: если дата напоминания больше текущей, вычисляется задержка `delay`. Создается таймер `setTimeout`, а его идентификатор сохраняется в коллекции `activeTimers = new Map()`. Это гарантирует отправку пуша строго в назначенное время.
- **Отложить на 5 минут (Snooze)**: В `sw.js` в параметры уведомления добавлен массив `actions: [{ action: "snooze", title: "Отложить на 5 минут" }]`.
- **Фоновая обработка действий**: При клике на кнопку "Отложить", срабатывает событие `notificationclick` в Service Worker. Воркер (даже если все вкладки браузера закрыты) делает скрытый `fetch` запрос на `POST /snooze`. Сервер находит старый таймер, отменяет его через `clearTimeout` и заводит новый ровно на 5 минут.
